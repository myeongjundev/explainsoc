**보안 AI의 99점, 처음 보는 공격에서도 99점일까요?**

보안 AI 제품 소개서의 “정확도 99%”가 어떤 시험의 점수인지 확인하고, 판매 업체에 물어볼 질문으로 바꿔 주는
웹 도구입니다. 10번 과제에서 쓴 논문 [ExplainSOC Research](https://github.com/myeongjundev/explainsoc-research)의
결과 — 같은 AI가 이미 배운 종류의 공격 시험에서는 99.8점, 처음 보는 공격 시험에서는 38.7점(Macro F1 × 100) —
를 제품 검토 규칙 15개로 옮겼습니다. SKT ALEPH 마지막 과제 B입니다.

**[공개 사이트에서 바로 써 보기 →](https://myeongjundev.github.io/explainsoc/)** 로그인·설치 없이, `예시로 바로 보기`
한 번이면 결론과 업체 질문까지 갑니다.

## 보안 업무에서 이 앱이 맡는 구간

보안 담당자가 AI 탐지 제품을 들여올 때의 흐름에서, ExplainSOC는 **성능표 검토 → 부족한 증거를 질문으로** 바꾸는
구간을 돕습니다.

```text
벤더 제안서 수신
→ PoC 성능표 검토          ┐
→ 시험 조건 확인            │
→ 탐지율·오탐률 함께 읽기    │  ExplainSOC
→ 미관측 공격 검증 여부 확인  │
→ 부족한 증거를 질문         ┘
→ PoC 추가 검증
```

- **탐지율과 오탐률은 함께 읽습니다.** 논문에서 매우 낮은 오탐률(FPR 0.0002)은 모델이 거의 모든 흐름을 정상으로
  예측한 결과였습니다(공격 Recall 0.0007).
- **학습 자료와 운영 트래픽은 다릅니다.** 운영에서는 학습 때 보지 못한 공격이 들어올 수 있어, 그런 공격만 따로 둔
  시험 결과가 있는지 묻습니다.
- **설명(XAI)이 있다고 잘 잡는 것은 아닙니다.** 설명 상위 특징이 세 번 모두 같았던 모델이 공격을 거의 놓쳤습니다.
- ExplainSOC는 IDS·IPS·SIEM을 대체하지 않고 트래픽을 직접 분석하지 않습니다. 받은 성능 주장을 읽는 의사결정
  보조 도구입니다.

## 누구를 어떻게 돕는가

> 보안 AI 도입을 처음 맡은 주니어 보안 담당자가 제품 소개서의 성능 숫자 한두 개를
> 받았을 때, 이 앱이 무작위 분할 XGBoost의 Macro F1 0.9979가 미관측 공격 스트레스
> 테스트에서 0.3871로 하락한 논문 결과를 근거로 그 숫자가 말하지 않는 평가 조건과
> 클래스별 오류를 드러내고, 공급자에게 바로 물을 질문을 만들어 준다.

## 사용자가 할 일 세 가지

1. 받은 소개서 문장을 붙여 넣거나(**소개서 문장 붙여 넣기**), 받은 성능 숫자를 적거나(**숫자로 직접 입력**),
   준비한 것이 없으면 **예시로 바로 보기**를 누른다. 예시는 첫 화면의 99.88%(논문 무작위 분할 결과)이고,
   결과에서 `다른 예시`로 같은 AI를 처음 보는 공격으로 시험한 결과를 볼 수 있다.
2. 분할 방식, 미관측 공격 포함 여부, 중복 제거 여부에 `예 / 아니오 / 모름`으로 답한다.
3. 근거 확인표에서 빠진 것을 확인하고, 질문별 답변 상태·메모를 남긴 뒤 PoC 검토표를 복사하거나 PDF로 저장한다. 공급자 답변이 오면 새 회차에서 해결됨·남음·새로 생김을 비교한다.

모르는 칸은 비워 두면 됩니다. 이 앱에서는 **모름이 가장 중요한 답**입니다 — 공급자에게 물을
질문으로 바뀝니다.

### 입력과 결과 화면을 읽는 순서

소개서 문장을 붙여 넣으면 그 문장이 그대로 다시 나오고, 성능 숫자·최고 성능 주장·분할 방식·신종 공격 탐지
주장·중복 제거·설명 가능한 AI 주장 위에 번호 표시가 붙습니다. 번호마다 읽은 값, 논문 근거, 그 표시로 생긴
질문을 메모로 달고, 소개서에 없어 질문이 된 조건은 따로 모읍니다. 판독은 정해 둔 표현을 찾는 규칙이며 AI를
부르지 않습니다. 놓친 것은 `빠진 조건 직접 답하기`에서 답합니다. 화면의 예시 소개서는 논문 숫자를 빌린
**가상의 문장**입니다.

처음 입력은 질문 여섯 개를 한 화면에 하나씩 묻습니다(`질문 N / 6`). 답하지 않고 넘긴 질문은 `모름`처럼
공급자에게 물을 질문으로 남습니다. 결과에서 `입력 수정`을 누르거나 다음 회차를 적을 때는 여섯 질문을
한 페이지에서 한꺼번에 고칩니다.

결과 맨 위에는 **결론 카드**가 있습니다. 결론 한 문장, 왜?(시험 조건 한 줄과 받은 숫자 한 줄), 그래서?(업체에
물을 질문 수)를 먼저 말합니다. 처음 보는 공격으로 시험했다는 근거가 없으면 논문에서 같은 AI가 99.8점에서
38.7점이 된 막대를 함께 보여 줍니다. 결론은 제품이 좋다·나쁘다는 판정이 아니라 광고 숫자만으로 믿을 근거가
있는지입니다.

그 아래 한 줄 **검토 요약**은 회차와 확인 필요·해석 주의·다음 질문 수만 알립니다. 결과 목차에서
`① 주장과 근거 → ② 판독 → ③ 다음 행동`을 한 번에 한 장씩 읽고, 회차 기록은 공급자 답변을 이어 붙일 때
펼칩니다. `업체에 물을 질문 보기`를 누르면 ③ 다음 행동의 질문으로 갑니다. 질문마다 상태(확인 필요·해석 주의)와
**왜 묻나요** 한 줄이 붙고, `질문만 복사`·`자료 요청서 복사`·`검토표 전체 복사`로 회의·메일·PoC 체크리스트에 옮깁니다.

| 입력을 서버로 보내지 않는다 | 받은 성능 자료를 브라우저 메모리에만 두고, 콘텐츠 보안 정책(`connect-src 'none'`)으로 요청 자체를 막는다. | `DESIGN.md` 3·14절 |

## 논문의 무엇을 쓰는가

반영한 논문 · **데이터 분할 방식에 따른 XAI 기반 네트워크 침입 탐지 성능과 설명 안정성 분석**

| 분할 | Accuracy | Macro F1 | 공격 Recall | FPR | 공격 탐지 |
|---|---:|---:|---:|---:|---|
| 계층화 무작위 분할 | 0.9988 | 0.9979 | 0.9974 | 0.0009 | 85,175건 중 84,955건 |
| 미관측 공격 스트레스 테스트 | 0.6299 | 0.3871 | 0.0007 | 0.0002 | 220,788건 중 160건 |

같은 방식으로 학습한 XGBoost라도 무엇을 시험했느냐에 따라 결과가 이렇게 달랐습니다. 앱은 이
결과에서 나온 판독 규칙 열 개(R01~R10), 입력 정합성 규칙 세 개(R11~R13), 후속 자료의 시험 출처를 확인하는 규칙(R14),
설명 가능한 AI 주장을 읽는 규칙(R15)으로 사용자가 받은 숫자와 문장을 읽습니다. 주장한 지표와 혼동행렬 계산값이 다르거나, 평가 조건 답변이 서로 모순되는 경우도 다시
확인할 질문으로 바꿔 줍니다. 예를 들어 오탐률만
있고 공격 Recall이 없으면, 논문에서 "매우 낮은 FPR 0.0002"가 실제로는 거의 모든 흐름을 정상으로
예측한 결과였다는 원문(원고 V-2)을 보여 주고 "같은 시험에서 공격 Recall은 얼마입니까?"라는 질문을
만듭니다.

앱이 쓰는 원문과 수치는 모두 [`src/data/paperEvidence.ts`](src/data/paperEvidence.ts) 한 곳에
있고, 화면의 모든 수치는 근거 ID(P01~P14)와 원고의 절로 되돌아갈 수 있습니다. 예시 혼동행렬은
원고의 반올림된 비율에서 거꾸로 계산하지 않고, 제출된 연구의 DAY-2 보고서 원수치를 씁니다.

### 논문 실험실

첫 화면의 **논문 실험실** 카드에서 논문의 뒤쪽 절반(원고 V-2~V-5)을 직접 바꿔 봅니다.

| 실험 | 원고 | 직접 바꾸는 것 |
|---|---|---|
| 1. 1위는 시험이 정합니다 | V-2 | 시험 두 가지 × 기준 세 가지(Macro F1·공격 Recall·FPR)로 XGBoost·Random Forest·Logistic Regression 순위 |
| 2. 운이 아니었습니다 | V-2 | XGBoost 학습 시드 세 개의 결과 |
| 3. 설명도 시험을 탑니다 | V-3 | 두 시험의 SHAP 상위 5개 특징과 순위 이동 |
| 4. 설명이 안정적이라고 잘 잡는 것은 아닙니다 | V-4 · V-5 | 설명 안정성(Top-5 Jaccard)과 공격 Recall, 상위 특징을 0~5개 지웠을 때 예측이 바뀐 비율 |

실험실은 새 숫자를 계산하지 않고 논문과 제출된 연구 보고서의 숫자만 옮깁니다. 소개서 판독 메모와 결론
카드에서 관련 실험으로 바로 갈 수 있습니다.

### 이 앱이 하지 않는 말

- 모델이 좋다거나 나쁘다는 판정, 신뢰 점수, 등급, 합격선
- 입력한 숫자와 논문 숫자의 우열 비교
- 다른 데이터셋이나 실제 조직망에 대한 일반화 — 결과는 2017년 합성 환경인 CICIDS2017 한
  데이터셋에 한정됩니다
- 날짜 기반 분할을 순수 시간 일반화라고 부르는 것 — 날짜와 공격 유형이 함께 바뀌어 둘을
  나누지 못했으므로 미관측 공격 스트레스 테스트라고 부릅니다
- SHAP을 공격의 원인으로 읽는 것 — 모델 내부 판단의 기여도일 뿐입니다

## 실행

Node.js 24 LTS(24.15 이상)가 필요합니다. 22.x라면 22.22.2 이상이면 됩니다. 새 폴더에서 다음 세
줄이면 됩니다.

```text
npm ci
npm run build
npm run preview
```

브라우저에서 `http://127.0.0.1:4173/explainsoc/`를 엽니다.

### 실행 묶음(ZIP)

제출용 ZIP은 `npm run release:zip`으로 만듭니다. 커밋된 소스, `package-lock.json`, 이 README,
예시 데이터(`src/data`), 테스트, 라이선스(`LICENSE`)만 담고 `node_modules`, Git 기록, 빌드 결과,
로그, 환경 파일은 담지 않습니다. 과제 기록인 `evidence/`와 `planning/`도 저장소에만 있습니다. 같은
커밋에서 다시 만들면 같은 파일(같은 SHA-256)이 나옵니다.

### 환경 변수

**필요한 환경 변수 없음.** 앱은 런타임 AI 서비스, 백엔드, 분석 도구를 쓰지 않아 API 키나 비밀값이
필요 없습니다. `.env` 파일은 `.gitignore`로 막혀 있습니다.

## 검사

테스트 수보다 무엇을 지키는지가 먼저입니다.

- 화면의 모든 논문 수치는 [`src/data/paperEvidence.ts`](src/data/paperEvidence.ts) 한 곳에서 오고, 단위 테스트가 원고 표의 값과 대조합니다.
- 판독 규칙 R01~R15가 어떤 입력에서 켜지고 어떤 질문을 내는지 단위 테스트로 고정해, 화면의 질문이 논문 규칙과 어긋나지 않게 합니다.
- 실제 브라우저에서 예시·소개서·숫자 입력·실험실·회차 흐름과 WCAG 2.2 AA, 375px, 키보드, 외부 요청 없음을 검사합니다.
- `main`에는 이 검사를 모두 통과한 커밋만 GitHub Pages로 배포하고, 배포된 자산의 SHA-256을 로컬 빌드와 대조합니다. 제출용 ZIP은 같은 커밋에서 늘 같은 파일로 만들어집니다.

| 명령 | 하는 일 |
|---|---|
| `npm run check` | 비밀값·개인정보·사용자 폴더 경로·위험한 DOM API·외부 요청 검사, 빌드가 있으면 배포본의 보안 정책까지 |
| `npm test` | 단위·컴포넌트 테스트 — 계산식, 입력 검증, 소개서 판독, 판독 규칙 R01~R15, 결론 카드, 근거·실험실 데이터, 사례 파일, 검토표 동작 |
| `npm run test:e2e` | 실제 브라우저 검사 — 예시, 세 행동, 소개서 판독, 논문 실험실, 잘못된 입력, 키보드, 화면 폭, 접근성, 요청·저장소 |
| `npm run verify` | 위 셋과 프로덕션 빌드를 차례로 |

브라우저 검사는 로컬에서는 설치된 Chrome을, CI에서는 Playwright가 받은 Chromium을 씁니다.
브라우저와 서버 사이에서 페이지에 스크립트를 끼워 넣는 프로그램이 있는 PC에서도 앱이 실제로 한
일만 검사하도록, 테스트는 빌드 결과물을 네트워크 없이 바로 읽어 옵니다. 테스트마다 쿠키·저장소가
빈 새 브라우저 컨텍스트에서 시작합니다.

같은 브라우저 검사를 공개 주소에 돌리려면 `LIVE_URL`을 줍니다.

```bash
LIVE_URL=https://myeongjundev.github.io/explainsoc/ npm run test:e2e
```

`main`에 올라간 커밋은 GitHub Actions가 위 검사를 모두 통과시킨 뒤에만 GitHub Pages에 배포합니다
(`.github/workflows/deploy.yml`).

## 개인정보와 보안

- 붙여 넣은 소개서 문장과 입력한 값은 브라우저 메모리에만 있습니다. URL, 쿠키, `localStorage`에 넣지 않고, 새로 고치면
  사라집니다.
- 배포본에는 콘텐츠 보안 정책(`connect-src 'none'`)이 걸려 있어 앱 코드가 어디로도 요청을 보낼 수
  없습니다.
- `질문만 복사`는 질문 문장만 담습니다. `검토표 전체 복사`는 사용자가 명시적으로 누를 때만 입력 숫자와 메모를 클립보드에 담습니다.
- 질문 상태와 메모를 포함한 모든 작업 내용은 서버로 전송하지 않고, 새로 고치면 사라집니다.
- `사례 JSON 내려받기`를 직접 누르면 현재 숫자·질문 답변·출처 메모를 포함한 1 MiB 이하 버전 표시 파일을 기기에 저장합니다. 이 파일은 자동 저장하거나 업로드하지 않으며, 다시 열 때 스키마 전체를 검증합니다.
- 외부 글꼴, 외부 이미지, 추적 스크립트를 쓰지 않습니다.
