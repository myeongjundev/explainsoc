## 2. 왜 바꿨나

- V7 앱을 한 바퀴 돌려 본 뒤 사용자가 내부 UI를 전면 개편하기로 했다.
- 진단한 문제는 여섯 가지다.
  1. 길 안내가 세 겹이었다: 위 단계 1·2·3, 결과 안의 `REVIEW MAP 01~05`, 아래 `1/3` 장 이동.
  2. 첫 화면(어두운 남색)과 안쪽 화면(베이지 폼)이 다른 앱처럼 보였다.
  3. 영어 라벨이 많았다: `DECISION BRIEF`, `CLAIM & EVIDENCE`, `EVIDENCE MAP`, `FIRST QUESTION`, `CLAIM AUTOPSY`.
  4. 결과 1장에 같은 근거 목록이 두 번 나왔다.
  5. 상자 안에 상자가 3~4단으로 겹쳐 있었다.
  6. 입력 단계가 단순한 폼으로만 보였다.
- 사용자가 정한 방향:
  - 범위는 **화면 디자인만** 바꾼다. 판독 규칙 R01~R14, 수치, JSON, 보안 경계는 그대로 둔다.
  - 톤은 **밝고 깔끔한 문서형**으로 한다. 첫 화면도 포함한다.
  - 입력은 두 방식을 모두 만들어 비교했다. 그 결과 **처음 입력은 한 화면씩, 결과에서 고치거나 2회차 이후는 한 페이지**로 정했다.
- 한 화면씩을 먼저 두는 이유: 이 앱의 대상은 주니어 담당자다. 지금까지의 관찰(card-5)에서 실패 원인은 "한꺼번에 너무 많이 보임"이었다. "모름"을 부담 없이 고르게 하려면 질문 하나와 설명 하나가 한 화면에 있어야 한다. 이미 질문을 한 번 읽은 사람은 한 페이지에서 바뀐 것만 고치는 편이 빠르다.
- 이 이유는 추론이다. 새로운 처음 보는 사람 재시험(BRB-C11)에서 실제로 확인해야 한다.

## 3. 바뀐 것

### 3-1. 입력

| 상황 | 화면 |
|---|---|
| 첫 화면 → `내 성능표 검토` | **한 화면씩** (`GuidedInput`) — 질문 6개, `질문 N / 6` 진행 막대 |
| 결과 → `입력 수정` / 평가 조건 확인 | **한 페이지** (`OnePageForm`) |
| 결과 → 다음 회차 저장 | **한 페이지** |
| 한 화면씩 → `질문 전체 한 번에 보기` | 한 페이지로 전환 (입력값 유지) |

- 한 화면씩의 질문 순서: ① 성능 숫자 ② 최고 모델이라고 소개했는지 ③ 혼동행렬 ④ 분할 방식 ⑤ 미관측 공격 ⑥ 중복 제거.
  - ①~③은 1단계(받은 숫자), ④~⑥은 2단계(평가 조건)로 표시한다.
- 선택지는 큰 카드이고, 카드마다 한 줄 설명이 있다. "모름"은 점선 카드이며 "공급자에게 물을 질문이 됩니다"라고 적었다.
- 접혀 있던 "용어 도움말"을 **"왜 묻나요?"** 상자로 바꿔 늘 보이게 했다.
- 답하지 않은 질문은 `건너뛰고 다음`으로 넘긴다. 판독 규칙은 원래 `null`을 `unknown`으로 처리하므로(`reviewRules.ts`의 `splitOf`·`unseenOf`·`dedupOf`) 결과는 같다.
- 질문을 넘기면 초점이 새 질문 제목으로 간다.
- 한 페이지 폼은 흰 문서 한 장에 두 구역을 둔다: **A 받은 숫자**(1~3번), **B 평가 조건**(4~6번).
  - 선택지는 붙은 단추 한 줄이고, 설명은 한 줄로 늘 보인다.
  - 아래에 `N / 6 답함`과 `결과 보기` 버튼이 스크롤해도 붙어 있다.
  - 390px에서는 선택지를 같은 너비의 칸으로 맞춘다.
- 2회차의 "이전 값: …"과 "변경: 이전 값을 ‘예’에서 ‘모름’으로 바꿉니다" 안내는 두 방식 모두에 있다.

### 3-2. 첫 화면

- 짙은 남색 배경을 흰 문서 카드로 바꿨다. 위 설명 칩은 연한 파랑이다.
- 오른쪽 그림은 연한 종이 톤이다. `99.88%`만 파랑으로 강조한다. 무작위 분할 막대는 검정, 미관측 공격 막대는 빨강이다.
- `CLAIM AUTOPSY` 라벨을 없앴다. 문구, 논문 링크, 개인정보 안내는 바꾸지 않았다.

### 3-3. 결과

- 단계 이름: `PoC 검토표` → **`검토 결과`**, 제목 `3. PoC 검토 작업대` → **`3. 검토 결과`**.
  - 결과물 이름 "PoC 성능 주장 검토표"는 담당자가 회의에 가져가는 문서 이름이라 그대로 두었다.
- 검토 요약(구 Decision Brief):
  - 어두운 박스를 흰 카드와 파란 윗선으로 바꿨다.
  - `검토 요약 · 1회차`, `가장 먼저 물을 질문`.
  - `판정 아님 · 근거 확인` 배지는 숫자를 가리지 않는 자리로 옮겼다.
- 결과 목차(구 REVIEW MAP):
  - 번호가 붙은 밑줄 탭 ①주장과 근거 ②판독 ③다음 행동을 두고, 오른쪽에 `회차 기록`·`검토표` 링크를 둔다.
  - 모바일에서는 탭 세 칸만 보인다.
  - 번호는 `aria-hidden`이라 버튼 이름은 "판독"처럼 한국어 제목만 읽힌다.
- 장 머리: 영어 라벨 대신 번호 원, 제목, 한 줄 설명을 둔다.
- 검토표(dossier): 어두운 남색을 흰 바탕과 검정 윗선으로 바꿨다.
- 회차 기록 펼침: `04` 대신 `+` 아이콘을 쓰고, 열면 아이콘이 회전한다.
- 요약·목차·장·회차 기록·버튼을 모두 **960px 한 열**로 맞췄다. 위 단계 버튼도 같은 폭이다.
- 색 토큰:
  - 새로 추가: `--accent #2450c7`, `--accent-soft #eef2fc`
  - 배경: `--paper #f4f5f7`
  - 베이지 계열 하드코딩 색은 차가운 회색으로 바꿨다.
  - `--midnight`·`--electric` 토큰은 남아 있지만 이제 쓰는 곳이 없다.

   - 쓰지 않는 `--midnight`·`--midnight-2`·`--electric` 토큰과 `.board-column` 옛 규칙(V7 절)을 정리한다.

## 6. 지켜야 할 경계 (그대로)
