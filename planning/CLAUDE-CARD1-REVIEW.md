## 2. 공통으로 지킬 경계

- 논문 수치는 원고에 있는 값만 사용한다.
- 결과는 2017년 합성 환경인 CICIDS2017 한 데이터셋에 한정한다.
- 날짜 기반 분할은 미래 성능이나 순수 시간 일반화가 아니라 **미관측 공격 스트레스
  테스트**라고 부른다.
- Logistic Regression 결과를 근거로 단순한 모델이 항상 더 잘 일반화한다고 말하지 않는다.
- SHAP은 공격 원인이 아니라 모델 내부 판단의 기여도다.
- 실제 SOC 분석가 평가나 사용성 연구를 했다고 말하지 않는다.
- 앱은 모델을 합격·불합격 또는 좋음·나쁨으로 판정하지 않는다. 확인된 사실과 더 확인할
  질문을 구분한다.
- 로그인·계정·초대·CAPTCHA·API 키 없이 공개할 수 있어야 한다.
- 실제 개인정보나 PCAP을 받지 않는다. 예시 데이터와 사용자가 직접 입력한 집계 수치만
  브라우저 안에서 처리한다.

## 3. 후보 1 — ExplainSOC Evidence Gate

### 카드 1 문장 초안

> 보안 AI 도입 전에 성능 근거를 검토해야 하는 주니어 보안 담당자가 모델 성적표를 받을
> 때, 이 앱이 무작위 분할 Macro F1 0.9979가 미관측 공격 스트레스 테스트에서 0.3871로
> 하락한 논문 결과를 바탕으로 평가 조건과 클래스별 오류를 확인하고, 검증된 사실·확인되지
> 않은 주장·추가 질문을 한 장의 검토표로 정리해 준다.

### 사용자가 할 일 세 가지

1. 평가 조건을 기록한다.
   - 데이터 분할 방식
   - 학습에 없던 공격의 시험 포함 여부
   - 중복 및 학습·시험 중복 제거 여부
   - 사용한 데이터셋
2. 성능 근거를 입력한다.
   - Accuracy, Macro F1, 공격 Recall, FPR
   - 또는 혼동행렬 TN·FP·FN·TP
   - SHAP을 근거로 썼다면 설명 안정성과 출력 민감도 확인 여부
3. 한 장 검토표를 확인한다.
   - `확인됨`, `확인 필요`, `해석 주의`
   - 담당자에게 물어볼 다음 질문
   - 각 안내가 나온 논문 절과 원문 근거

### 제품 경험 초안

```text
첫 화면
→ 60초 예시 또는 내 성적표 선택
→ 평가 조건 입력
→ 지표 또는 혼동행렬 입력
→ Evidence Map
→ 확인됨 / 확인 필요 / 해석 주의
→ 다음 질문과 논문 근거
→ 인쇄 가능한 한 장 검토표
```

### 차별점

- 점수를 다시 보여 주는 대시보드가 아니라 **성능 주장을 검토 가능한 질문으로 바꾼다.**
- 모르는 입력을 실패로 처리하지 않고 `확인해야 할 질문`으로 바꾼다.
- 임의의 신뢰 점수나 합격선을 만들지 않아 논문의 해석 경계를 지킨다.
- 평가 설계, 입력 검증, 근거 추적, 보고서 출력을 한 흐름으로 보여 줄 수 있다.
- 정적 React 앱과 브라우저 내부 상태만으로 구현할 수 있다.

### 위험

- 입력 항목이 많으면 체크리스트처럼 보이거나 첫 사용이 길어질 수 있다.
- 한 장 검토표까지 욕심내면 핵심 판독보다 출력 디자인에 시간이 많이 들 수 있다.
- `확인됨`이 모델의 품질을 보증한다는 뜻으로 읽히지 않도록 문구 설계가 필요하다.

## 4. 후보 2 — SplitLens

### 카드 1 문장 초안

> 침입 탐지 모델의 평가를 설계하거나 결과를 읽는 학생·주니어 분석가가 학습과 시험의
> 공격 유형을 나눌 때, 이 앱이 무작위 분할의 높은 성능이 미관측 공격 탐지 능력을
> 보증하지 않았던 논문 결과를 바탕으로 두 집합의 공격 노출 관계와 중복 확인 상태를
> 시각화하고, 관측 공격 평가와 미관측 공격 스트레스 테스트를 구분하도록 돕는다.

### 사용자가 할 일 세 가지

1. 학습 집합과 시험 집합의 공격 유형을 입력하거나 예시 구성을 불러온다.
2. 분할 방식, 중복 제거 여부와 필요한 경우 보고된 지표를 입력한다.
3. 공격 노출 행렬과 평가 범위 설명을 보고, 현재 시험이 무엇을 검증하며 무엇을 검증하지
   못하는지 확인한다.

### 제품 경험 초안

```text
첫 화면
→ 논문 예시 또는 내 분할 선택
→ 학습·시험 공격 유형 배치
→ Attack Exposure Matrix
→ 관측 / 미관측 / 확인 불가 구분
→ 평가 범위와 다음 실험 질문
```

### 차별점

- 공격 유형을 직접 배치하고 관계를 보는 화면이라 시각적 인상이 강하다.
- 논문의 핵심인 `분할 방식이 결론을 바꾼다`를 인터랙션으로 이해시킨다.
- 데이터·모델 평가 설계 능력을 포트폴리오에서 보여 주기 좋다.
- 기존 ExplainSOC 결과 대시보드와 역할이 분명히 다르다.

### 위험

- 사용자가 공격 유형과 데이터 분할 개념을 모르면 1분 안에 이해하기 어렵다.
- 논문은 날짜 변화와 공격 유형 변화를 분리하지 못했으므로 시각화가 순수 시간 일반화
  분석처럼 읽히면 안 된다.
- 단순 목록 입력만 제공하면 전문 도구처럼 보이지만 실제 효용은 좁을 수 있다.
- 다양한 사용자 데이터셋에 일반화된 분할 규칙을 논문 결과인 것처럼 만들 위험이 있다.

## 5. 결합안 — Evidence Gate 안의 SplitLens

Evidence Gate를 전체 앱으로 두고 SplitLens를 평가 조건 단계의 시각화 하나로 넣는 안이다.

```text
60초 예시
→ 성능표 판독
→ 공격 노출 관계를 아는 경우 SplitLens로 입력
→ Evidence Map과 한 장 검토표
```

이 결합안은 Evidence Gate의 쉬운 입구와 SplitLens의 시각적 차별화를 함께 얻을 수 있다.
반대로 첫 판의 범위가 커져 완성도가 낮아질 수 있다. 결합한다면 SplitLens는 학습·시험 공격
유형의 `관측`, `미관측`, `정보 없음`만 보여 주고 일반화 성능을 예측하지 않아야 한다.

## 6. 비교 기준

아래 기준을 각각 5점 만점으로 평가해 달라. 점수만 주지 말고 근거를 한두 문장씩 적는다.

| 기준 | 확인할 질문 |
|---|---|
| 과제 적합성 | 논문 결과를 실제로 쓰고 C01~C05를 명확히 통과하는가? |
| 1분 이해 | 처음 온 사람이 대상과 도움을 즉시 이해하는가? |
| 논문 충실성 | 논문 수치와 해석 경계를 과장 없이 옮길 수 있는가? |
| 차별화 | 기존 결과 대시보드나 흔한 혼동행렬 계산기와 다른가? |
| 포트폴리오 가치 | 기획·프론트엔드·검증·보안/AI 이해를 함께 보여 주는가? |
| 완성 가능성 | 남은 기간 안에 모바일·접근성·테스트까지 높은 완성도로 만들 수 있는가? |
| 확장성 | 첫 판을 해치지 않고 이후 기능을 더할 수 있는가? |

## 7. Claude가 답할 것

다음 순서로 명확하게 답해 달라.

1. **결론:** Evidence Gate, SplitLens, 결합안 가운데 하나를 추천한다.
2. **추천 이유:** 가장 강한 이유 세 가지를 적는다.
3. **버릴 것:** 선택하지 않은 안에서 첫 판에 넣지 말아야 할 것을 적는다.
4. **실패 가능성:** 추천안이 과제나 포트폴리오에서 실패할 수 있는 지점 세 가지와 줄이는
   방법을 적는다.
5. **카드 1 최종 후보:** `○○인 사람이 △△할 때 이 앱이 □□을 해 준다` 구조로 한 문장을
   제안한다. 돕는 사람, 앱이 하는 일, 논문의 어느 결과를 쓰는지가 모두 들어가야 한다.
6. **사용자가 할 일 세 가지:** 처음 온 사람이 설명 없이 실행할 수 있는 행동으로 적는다.
7. **첫 화면 10초 문구:** 제목 하나, 보조 문장 하나, 첫 버튼 이름 하나를 제안한다.
8. **범위:** 첫 판 필수 기능과 승인 뒤 기능을 나눈다.
9. **최종 반론:** 본인의 추천을 선택하지 말아야 할 가장 강한 이유도 하나 적는다.

사용자 대신 최종 결정하지 않는다. 원고에 없는 숫자, 임의 임계값, 신뢰 점수, 모델 합격
판정을 만들지 않는다.
